# AI Sales Coach

An interactive discovery-call scenario. The learner hears a prospect objection, chooses a response, and gets tailored coaching feedback generated by Gemini.

**[Try it live →](https://ai-sales-coach-exp.vercel.app)**

## Run it locally

```sh
npm install
cp .env.example .env.local   # then add your Gemini API key
npm run dev                  # http://localhost:3000
```

## How it fits together

```
Browser                         Next.js server (/api/coach)             Gemini
───────                         ───────────────────────────             ──────
scenario + choice id  ───────▶  looks up scenario and choice
                                builds the coaching prompt     ──────▶  generates feedback
feedback streams in   ◀──────  streams text back              ◀──────
```

- **Content is data.** Everything a learner sees lives in [`src/scenarios/*.json`](src/scenarios/), separate from the code that runs it. Each choice also carries an `intent` (what the response does, in the designer's words) that guides the coach. Adding a scenario means adding a file, not rebuilding screens.
- **The key and prompt stay server-side.** The browser sends only a scenario ID and choice ID. The server rejects anything that isn't in a scenario file, so the endpoint can't be used to send arbitrary prompts.
- **Feedback streams.** Text appears as Gemini writes it rather than after the full response arrives.

## Project layout

| Path                         | What it is                                                    |
| ---------------------------- | ------------------------------------------------------------- |
| `src/scenarios/`             | Scenario content (setup, objection, choices and their intent) |
| `src/lib/prompt.ts`          | The coaching prompt and Gemini model (server only)            |
| `src/app/api/coach/route.ts` | API route that calls Gemini and streams the reply             |
| `src/lib/coach.ts`           | Browser client for that route                                 |
| `src/hooks/useWordStream.ts` | Word-by-word reveal (skipped for reduced-motion users)        |
| `src/components/`            | Intro, question, and feedback screens                         |

## Accessibility

- Streamed text is hidden from screen readers; the full text is announced once instead of word by word.
- Respects `prefers-reduced-motion` and `prefers-color-scheme`.
- Real buttons, a native `<dialog>`, and visible keyboard focus.
